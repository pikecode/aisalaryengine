# 打卡弹窗设计稿

## 背景

当前首页头部已经有“打卡”入口，但点击后的交互尚未实现。用户提供了明确的视觉参考，要求先完成弹窗展示与“点击展开”交互，登录与打卡状态判断后续再补。

## 目标

- 点击头部“打卡”后打开一个居中的弹窗
- 弹窗默认展示主视觉与基础打卡内容
- 保留“点击展开”交互，展开后显示完整连续打卡区域
- 后续可方便接入登录判断、重复打卡判断、奖励状态判断

## 范围

### 本次要做

- 头部“打卡”按钮触发弹窗
- 弹窗遮罩、关闭、进入/退出动画
- 默认态与展开态两种视觉状态
- PC 与 H5 如有需要可共享结构，样式按断点适配

### 本次不做

- 登录校验
- 当天是否已打卡校验
- 会员/权限校验
- 后端打卡接口
- 奖励发放逻辑

## 设计方案

### 方案 A：在头部组件内直接写弹窗

优点：最快。

缺点：头部文件会继续膨胀，后续补交互时不利于维护。

### 方案 B：独立 `CheckinModal.vue`，头部只负责打开

优点：结构清晰，弹窗逻辑集中，后续补登录和状态判断最方便。

缺点：需要新增一个独立组件。

### 方案 C：做成全局弹层状态

优点：以后任何页面都能触发。

缺点：当前只有头部入口，复杂度过高。

### 推荐

采用 **方案 B**。当前需求只有一个入口，独立弹窗组件最合适，也最容易对齐视觉稿。

## 组件设计

### 1. 头部组件

`AppHeaderPC.vue` 和 `AppHeaderH5.vue` 继续保留“打卡”按钮，但只负责触发弹窗打开，不放具体弹窗结构。

可通过一个共享状态或事件把 `open` 传给弹窗组件。

### 2. 打卡弹窗组件

建议新增 `src/components/common/CheckinModal.vue`。

职责：

- 控制遮罩显示
- 控制弹窗居中层
- 管理 `expanded` 展开态
- 处理关闭动作
- 预留后续接入状态字段的接口

### 3. 状态字段

初版只需要：

- `open`：是否打开
- `expanded`：是否展开连续打卡区

后续再扩展：

- `loggedIn`
- `checkedToday`
- `rewardState`
- `streakDays`

## 交互设计

1. 点击头部“打卡”按钮
2. 打开半透明遮罩和弹窗
3. 默认展示主视觉、说明文案、底部主按钮
4. 点击“点击展开”后，展开连续打卡区
5. 点击遮罩、关闭图标关闭弹窗
6. 后续补登录状态时，可在打开前先拦截

## 数据流

- Header 接收用户点击
- Header 触发 `CheckinModal` 的打开状态
- `CheckinModal` 负责内部展开状态
- 后续如果接入业务状态，状态只需要从父级传入即可

## 视觉实现原则

- 尽量贴合用户给的参考图
- 默认态先保证整体轮廓、层级、按钮和背景一致
- 图中“点击展开”作为明确的折叠/展开入口
- 先保证结构正确，再做细节微调

## 边界与风险

- 如果弹窗视觉在 PC 和 H5 差异很大，再拆分为 `CheckinModalPC.vue` 与 `CheckinModalH5.vue`
- 如果后续需要多个页面都能唤起打卡，则再考虑提升为全局弹层状态

## 验收标准

- 点击头部打卡按钮能打开弹窗
- 弹窗可关闭
- “点击展开”能切换展开/收起
- 默认态和展开态都能按参考图表达层级
- 代码结构保持清晰，不把弹窗逻辑塞进头部组件里
